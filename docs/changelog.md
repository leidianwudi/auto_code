# .ac 语言变更日志与兼容性策略

> 本文件记录 `.ac` 语言、模板语法、内置函数签名、字节码格式的**对外可见变更**。
> 内部实现重构（不改行为）不记录。

## 兼容性策略（内部长期项目版）

1. **破坏性变更必须先废弃后移除**：改语法 / 改内置函数签名 / 改错误语义时，
   旧写法先保留并输出 `warning: ... is deprecated`，至少运行一个版本周期后才可移除。
2. **字节码缓存有版本戳**：`AcBytecodeCache::engineCacheVersion()`（当前 = 3）。
   字节码语义/格式变化时**必须递增**，旧缓存自动全量失效，不产生错读。
   失效键另含入口内容 + 直接/传递 import 内容 + `builtin.d.ac` 内容。
3. **每次破坏性改动前做存量普查**：在公司内搜索受影响的 `.ac` / `.tpl` 文件，
   评估影响面后动手；golden 测试（tests/test_golden_script.cpp）是行为基线，
   改语义先跑它。
4. **脚本资产是业务资产**：各部门散落的脚本没有集中清单，破坏性改动的真实
   影响面永远比想象的大——宁可加别名/兼容层，不做静默断裂。

## 变更记录

### 2026-09（语言能力与引擎加固）

- **语言：新增 `try/catch/finally/throw`**（生成流水线"单表失败不中断整批"）：
  `throw` 的值即错误消息；catch 绑定错误文本；finally 保证执行。
  语义细节见 ac_language_spec.md §11.3。
- **语言：接口支持属性契约**（对象形状校验）：`interface Pt { let x: Number; let tag?: String }`，
  类 implements 时属性必须存在且类型兼容，`?` 属性可缺失。
- **语言：运行时非法操作显式报错**（对齐 JS TypeError，对 null 索引/属性/方法调用等
  报错中断，替代静默 no-op——单例数据丢失回归教训）。
- **语言：值语义定稿**（§11：JSON 数据值语义/深拷贝、类实例引用语义、`==` 精确定义）。
- **引擎**：`AcExecutor::execute()` 返回值类型 `QJsonValue` → `accore::AcJsonValue`
  （引擎值模型统一；UI 边界需要 QJson 时调 `toQJsonValue()`）。
- **引擎**：headless 新增 `--vm` 参数；环境变量 `AC_EXEC_MODE=vm` 全局灰度字节码模式。
  两者不改变脚本语义（对拍护栏：test_ac_vm.cpp 35 项 + golden dual-mode）。
